# 距离度量数学，实现 AI 代码相似度检测
代码相似度检测的本质，是用数学距离度量，量化两段代码之间的差异。很多人只知道余弦相似度，却分不清词法距离、语法树距离、语义向量距离各自的适用边界。一套可靠的AI代码克隆检测，是分层选用不同距离度量，从表层文本、语法结构到深层语义，逐层判断代码是否同源、逻辑是否等价。

距离度量有统一的数学公理：非负性、对称性、三角不等式。距离数值越大，代表两份样本差异越大；距离越小，相似度越高。不同度量，本质是在不同空间里定义“远近”，这也是区分它们能力的根源。

第一层是词法层面的字符串距离，典型是莱文斯坦编辑距离。它统计把一段代码转为另一段，最少需要多少次增、删、替换操作。它的优势是简单直观，适合检测直接复制、少量修改的代码。但短板很明显：对变量改名、换行调整、语句重排非常敏感，只要做简单的混淆改写，距离就会大幅升高，无法识别换皮克隆。N-Gram距离是它的补充，把代码切为连续词元窗口，统计重合片段，抗单字符改动能力更强，但依然只停留在文本表层，看不懂逻辑。

第二层是语法结构距离，也就是AST编辑距离。代码被解析成抽象语法树，不再看字面字符，而是看分支、循环、函数调用的节点结构。距离定义为两棵语法树之间增删替换节点的最小代价。同样逻辑的代码，哪怕变量名、注释全部改掉，只要控制流结构一致，AST距离依然很小；如果只是字面相似、逻辑不同，距离会被拉开。这一层解决了简单变量混淆的问题，适合识别结构克隆，但它依然很难理解等价异构写法，比如循环和递归实现同一个功能，语法树完全不同，AST距离会判定为不相似。

第三层是语义向量距离，也就是AI嵌入方案的核心。借助CodeBERT等代码预训练模型，把整段代码映射到高维语义向量空间，再用余弦距离、欧氏距离做比对。余弦距离关注向量夹角，不关心向量长度，适合代码长短不一的场景；欧氏距离关注空间直线距离，对向量模长敏感。AI模型在训练中学习了代码的功能语义，循环和递归等价实现、不同语言同逻辑代码，都能得到相近的向量，这是前两种距离做不到的。但它有缺陷：向量是近似压缩，容易出现误召回，逻辑完全不同的代码也可能向量靠近，不能单独作为判定依据。

工程上的落地思路，是多级距离串联校验，而不是单一指标。先用轻量的N-Gram距离做粗筛，快速过滤明显不相关代码；候选集进入AST编辑距离校验，过滤文本巧合重合；最后用代码嵌入的余弦距离做语义复核。三级距离共同输出分数，再通过阈值划分，区分完全相同、结构克隆、语义等价、无关代码。同时还会引入程序依赖图PDG的编辑距离，关注数据流向，进一步规避结构相近、数据逻辑不同的误判。

距离度量的选择，直接决定检测系统的成本与精度。字符串距离计算快，适合海量代码库初筛；AST距离计算开销中等，适合精准结构校验；语义向量推理成本最高，一般只用于候选子集。如果全部代码都跑大模型嵌入，算力成本会难以承受。

一个常见误区：余弦相似度就是万能指标。余弦只是向量空间里的一种距离度量，它看不见语法结构，也没有严格的程序逻辑约束。AI嵌入是强拟合，存在分布偏差，所以必须搭配语法距离做约束，不能只靠向量相似度下结论。

面向未来，代码相似度检测会走向自适应距离融合。系统自动根据代码类型，动态分配不同度量的权重，同时加入对比学习优化嵌入空间，让功能等价的代码距离更近，功能不同的代码距离更远。但底层逻辑不变：距离只是差异的量化标尺，不同空间的标尺，负责捕捉不同层级的代码信息。

总而言之，代码相似度检测依托分层距离数学：编辑距离衡量文本差异，AST编辑距离衡量语法结构差异，向量空间余弦距离衡量语义功能差异。多级距离组合，兼顾速度与准确性，才能可靠识别复制篡改、结构克隆、异构等价代码，支撑代码查重、开源合规、漏洞溯源等场景。（全文978字）
